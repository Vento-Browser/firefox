## 0. TL;DR (главное для решения)

- **Camoufox — это форк Firefox с антидетект-фингерпринтингом, реализованным на
  уровне C++** (перехват в самом движке, а не JS-инъекция в страницу). По
  архитектуре это **тот же путь, что выбрал Vento**: править Gecko в точках выдачи
  значений, а не подменять свойства из контента. Наша ключевая техническая ставка
  подтверждается независимой реализацией.
- **Но цель у Camoufox противоположная нашей по оси «случайность vs
  детерминизм».** Camoufox делает каждый инстанс **правдоподобно-уникальным живым
  устройством** (для параллельного скрейпинга/автоматизации через Playwright).
  Vento делает так, чтобы **разные машины с одним профилем выглядели одной и той
  же машиной на 100%** (см. §0 FINGERPRINTING_RESEARCH). Это разные продукты для
  разных сценариев, хотя механика перехвата почти одна.
- **Что заимствовать реально:** (1) их каталог поверхностей и `properties.json` как
  чек-лист/схему нашего Vento Fingerprint Profile; (2) БД реальных связок
  GPU→WebGL (`webgl_data.db`) и статистику BrowserForge — как источник
  правдоподобных **согласованных** значений; (3) приём анти-font-metrics
  (offset letter-spacing); (4) их набор leak-тестов и debug-flowchart как основу
  нашего E2E-стенда; (5) идею Juggler-изоляции автоматизации (нам не критично, но
  полезно знать). Лицензия — открытая (MPL-совместимый форк Firefox), заимствовать
  можно.
- **Чего у них нет, а у нас должно быть:** детерминированная идентичность между
  машинами; §9 сетевой отпечаток (TLS/HTTP2 JA3/JA4) они закрывают слабо; интеграция
  с backend-профилями/командами и своей панелью; свой прокси/гео-консистентность.

## 1. Что такое Camoufox

Антидетект-браузер, форк Firefox (на момент разбора — ветка v146.x-beta),
ориентированный на **автоматизацию через Playwright** и AI-агентов. Позиционируется
как «headless-first, <200MB, undetectable at scale». Главная фишка формулируется их
же словами: **«fingerprint injection & rotation without JS injection»** —
фингерпринт вшивается в браузер, а не накладывается скриптом, поэтому его нельзя
поймать инспекцией `Object.getOwnPropertyDescriptor`/прокси-ловушками, как ловят
классические stealth-плагины (puppeteer-extra-stealth и т.п.).

Продукт открытый (весь исходник опубликован), деньги, судя по всему, на этом не
берут; распространяется как Python-пакет (`camoufox[geoip]`) + бинарники браузера.

## 2. Архитектура (как это устроено технически)

### 2.1 Слой конфигурации: Python → env → C++ `MaskConfig`
1. Пользователь передаёт словарь свойств в Python API (`Camoufox(...)` /
   `launch_options`). Либо задаёт свои значения, либо получает
   авто-сгенерированный правдоподобный профиль.
2. `validate_config()` проверяет типы по манифесту **`properties.json`** (единый
   реестр всех спуфимых свойств и их типов).
3. `get_env_vars()` сериализует конфиг и **прокидывает его в браузер через
   переменные окружения** (с чанкованием, чтобы обойти лимит длины env у ОС).
4. Внутри C++ читается объект **`MaskConfig`** — «источник правды» для патчей.

### 2.2 Слой патчей: единый паттерн перехвата в Gecko
Каждый патч устроен одинаково:
```
если в MaskConfig задано значение X → вернуть X;
иначе → штатная реализация Firefox.
```
Так закрыты: геометрия окна, поля `navigator`, экран, WebGL-параметры,
WebRTC-IP, аудио-фингерпринт, геолокация, Battery API, голоса SpeechSynthesis и т.д.
**Это ровно наш подход из FINGERPRINTING_RESEARCH** (перехват в
`nsRFPService::GetSpoofed*` / canvas-хук / WebGL-санитайзер и подстановка значения
из профиля), только у них своя параллельная инфраструктура вместо
RFP-таргетов/`privacy.fingerprintingProtection.overrides`.

### 2.3 Источники правдоподобных значений (это их сильная сторона)
- **BrowserForge** — генератор фингерпринтов по **статистическому распределению
  реального трафика** (UA, hardwareConcurrency, экран, заголовки, battery).
  Маппинг во внутренние свойства — `from_browserforge()` + `browserforge.yml`.
- **`webgl_data.db`** — SQLite-база **реальных связок** GPU: `sample_webgl()`
  достаёт статистически корректные vendor/renderer + наборы параметров под целевую
  ОС. То есть vendor/renderer не берутся с потолка, а из реального «облака» устройств.
- **`update_fonts()`** — мержит стандартный набор шрифтов целевой ОС с
  пользовательскими, чтобы список был консистентен с UA.
- Приоритетный мерж (`merge_into()`/`set_into()`) — пользовательские значения не
  перетираются дефолтами; предупреждения о «палевных» комбинациях, глушатся флагом
  `i_know_what_im_doing`.

**Ключевой вывод:** самое ценное здесь — не механика перехвата (она у нас есть),
а **база согласованных правдоподобных значений**. Наш профиль тоже обязан быть
внутренне непротиворечивым (UA↔platform↔UA-CH↔шрифты↔WebGL — противоречие само по
себе становится отпечатком, см. §1 FINGERPRINTING_RESEARCH). BrowserForge +
`webgl_data.db` — готовый datasource для этого.

### 2.4 Автоматизация: Juggler вместо CDP
Camoufox использует протокол **Juggler** (родной для Firefox), а не CDP, и патчит
его так, что Playwright работает с изолированной «копией» страницы — сайт не видит
инъекций автоматизации в `window`. Плюс фиксы webdriver-детекта, headless-детекта,
виртуальный дисплей-буфер для headful-работы на headless-сервере. Для Vento
(интерактивный браузер для людей, не для скрейпинга) это **не приоритет**, но
механизм изоляции полезно иметь в виду, если появится авто-сценарий.

## 3. Фингерпринтинг: гарантии, покрытие, тесты

### 3.1 Покрытие поверхностей (их категории → наши §)
Config-категории Camoufox: Navigator, Cursor Movement, Fonts, Screen, Window,
Document, HTTP Headers, Geolocation & Intl, WebRTC IP, WebGL, Media & Audio,
Voices, Addons, Misc. Сопоставление с нашим разбором:

| Camoufox | Наш раздел (FINGERPRINTING_RESEARCH) | Комментарий |
|---|---|---|
| Navigator, HTTP Headers | §1 (UA/CH/platform/hwConcurrency…) | Совпадает 1:1 |
| Screen, Window, Document | §2 (экран/окно/DPI/CSS-media) | Совпадает |
| Fonts | §4 (список + метрики) | У них есть анти-metrics (см. §3.3) |
| WebGL, Media & Audio | §3, §5 (графика/аудио) | Разная стратегия по шуму (см. §3.2) |
| Geolocation & Intl, Voices | §7, §8 | Совпадает |
| WebRTC IP | §9 (частично) | У нас через `vento_proxy` |
| Cursor Movement | §10 (поведение) | У них — генерация «человеческой» мыши |
| — | **§9 TLS/HTTP2 JA3/JA4** | **У Camoufox фактически не закрыто** |

### 3.2 Canvas / WebGL: детерминизм у них тоже есть, но с другой целью
Важная и неочевидная деталь. По WebGL их документация **прямо запрещает
рандомить** vendor/renderer/extensions/precision: *«WAF хэшируют WebGL-фингерпринт
и сверяют с датасетом; случайные значения → детект как unknown device»*. Поэтому
**параметрический** WebGL у них **детерминирован из конфига** — и два инстанса с
одинаковым конфигом дают **одинаковый WebGL-хэш**. Это в точности наш вывод из §3
(параметрические поверхности прибиваются к профилю,
`webgl.override-unmasked-vendor/-renderer`).

А вот **canvas-пиксельный шум** и **font-metrics** у них наоборот **варьируются**,
чтобы хэш «правдоподобно плавал между сессиями» (модель живого устройства). Это
**противоположно нашей задаче** (нам нужен байт-в-байт идентичный readback между
машинами — §3, путь «унифицированный софт-рендер + детерминированный seed-шум»).
Вывод: их подход к параметрике мы подтверждаем и переиспользуем; их подход к
readback/метрикам нам **не подходит как есть** — нужен наш детерминированный seed
(замена случайного `GetBrowsingSessionKey`-UUID) поверх софт-рендера.

### 3.3 Font metrics
Camoufox глушит **font-metrics fingerprinting** «случайным офсетом letter-spacing»
+ автоподстановкой системных шрифтов под UA. Это закрывает канал §4 (метрики
глифов), который у нас честно висит в `residualVariance()` как нерешённый префами.
**Приём заимствуемый**, но у нас офсет должен быть **детерминированным из seed**
(иначе теряется идентичность между машинами), а не случайным.

### 3.4 Гарантии и тесты
- **Гарантия** Camoufox: «правдоподобно и внутренне-консистентно, необнаружимо
  через JS-инспекцию, значения из реального распределения». Это **вероятностная**
  гарантия («сойти за реальное устройство»), НЕ «две машины идентичны». Наша
  гарантия строже и другая (детерминированная идентичность).
- **Тесты:** у них нет строгого «оракула идентичности» — верификация через внешние
  leak-сайты **CreepJS, BrowserLeaks, BrowserScan** + встроенный **debug-flowchart**
  для пошагового поиска рассогласований. Для нас это готовый набор мишеней в E2E
  (§«Заметки по тестированию» FINGERPRINTING_RESEARCH): наш стенд должен гонять эти
  же сайты, но с **более сильным критерием** — совпадение JSON-снимков между двумя
  физически разными машинами, а не просто «зелёный» на CreepJS.

## 4. Совпадения и различия замыслов Camoufox vs Vento

### 4.1 Где замыслы совпадают
- **C++/движковый перехват вместо JS-инъекции** — общая базовая ставка. Оба
  считают JS-stealth-плагины тупиковыми (палятся на дескрипторах).
- **Внутренняя консистентность профиля** как первичное требование.
- **Параметрические поля (navigator/screen/WebGL-params/fonts-list) прибиваются к
  заданным значениям** — идентичный вывод у одинаковых конфигов достижим и нужен.
- **Firefox как база** (а не Chromium): у обоих один и тот же довод — по Chrome
  детект жёстче, CDP — широкая мишень, по Firefox больше запаса.
- **WebRTC/IP надо закрывать на уровне протокола** (у них — спуф IP, у нас — прокси).

### 4.2 Где принципиально расходятся
| Ось | Camoufox | Vento |
|---|---|---|
| **Цель** | Каждый инстанс — уникальное правдоподобное «живое» устройство | Разные машины с одним профилем — **одна и та же** машина на 100% |
| **Ось случайности** | Рандомизация canvas/metrics «под живого» | **Детерминизм** из общего seed профиля |
| **Сценарий** | Параллельный скрейпинг/автоматизация, AI-агенты, Playwright | Интерактивный браузер для людей/команд, мульти-аккаунтинг с общей личностью |
| **Модель профиля** | Локальный dict/env на запуск | **Backend-синхронизируемый профиль**, панель, команды, лицензии |
| **Сеть §9 (TLS/HTTP2)** | Практически не закрыто | Обязательная часть «100%» (билд+прокси, возможно патч NSS) |
| **Прокси/гео** | Опционально (geoip), IP-спуф | Свой `vento_proxy`, гео↔TZ↔locale консистентность |
| **UX** | Headless-first, для ботов | Полноценный десктоп-браузер, панель, автозаполнение, синк |

**Одной фразой:** Camoufox оптимизирован под «много разных правдоподобных
одноразовых личностей», Vento — под «одна общая воспроизводимая личность на многих
машинах». Механика перехвата ~70% общая, целевая функция обратная.

### 4.3 Преимущества Camoufox (что у них лучше прямо сейчас)
- Готовая **база правдоподобных согласованных значений** (BrowserForge +
  `webgl_data.db`) — у нас этого источника пока нет, профиль задаётся вручную.
- **Зрелость и охват поверхностей** уже в проде (навигатор, экран, WebGL, аудио,
  голоса, шрифты, battery, WebRTC-IP, human-cursor) — у нас это этап-2 PoC-модули.
- **Юзабельная авто-генерация** «rotate fingerprints» из коробки.
- Готовая **интеграция с Playwright/Juggler** и headless-инфраструктура.
- Публичный, проверяемый комьюнити код антидетекта → можно читать и заимствовать.

### 4.4 Преимущества Vento (что у нас сильнее/уникально)
- **Детерминированная идентичность между машинами** — Camoufox этого не делает и
  не ставит такой цели. Это наш дифференциатор.
- **§9 сетевой отпечаток** проработан (TLS/HTTP2/JA3/JA4 как константы билда +
  прокси + разбор GREASE) — у Camoufox это дыра.
- **Backend-профили, команды, лицензирование, панель, автозаполнение, синк
  логинов, session-vault** — это продукт, а не библиотека под ботов.
- Мы строим поверх **RFP/FPP-инфраструктуры Firefox** (готовые 81 таргет,
  `granularOverrides`, парсер overrides) — меньше расхождений с upstream, легче
  мерджить обновления Firefox. Camoufox тащит свой параллельный `MaskConfig`,
  который надо переносить на каждый ESR-апгрейд.

### 4.5 Недостатки Camoufox
- Вероятностная гарантия, нет строгого оракула идентичности/полноты (deny-by-default).
- Слабый сетевой слой (§9) — при жёстком WAF JS-профиль сойдётся, а JA3/HTTP2 выдаст.
- Рандом canvas/metrics ломает воспроизводимость (для нашего кейса — минус).
- Ориентация на headless/ботов → не десктоп-продукт; свой форк-мейнтенанс.
- «Слишком идеальная» human-cursor-синтетика сама может стать сигналом (наш вывод §10).

## 5. Что конкретно заимствовать (actionable)

1. **`properties.json` как схема нашего Vento Fingerprint Profile.** Взять их
   реестр свойств/типов/категорий как готовый чек-лист и сопоставить 1:1 с нашими
   RFP-таргетами (§«Первоочередные шаги» FINGERPRINTING_RESEARCH, п.1). Экономит
   проектирование структуры профиля.
2. **Источник согласованных значений.** Оценить прямое использование **BrowserForge**
   (генерация непротиворечивого профиля из реального распределения) и
   **`webgl_data.db`** (реальные связки GPU→WebGL vendor/renderer/params) как
   backend-datasource, который отдаёт готовые Vento-профили. Это закрывает нашу
   дыру «откуда брать правдоподобные согласованные значения».
3. **Паттерн `MaskConfig` для полей, которых нет в RFP-таргетах.** Там, где у
   Firefox RFP нет готового таргета (мелкие Document/Window-поля), их «check config
   → return / fallthrough» — минимальный образец точечного патча.
4. **Анти-font-metrics (letter-spacing offset)** — заимствовать механизм, но
   сделать офсет **детерминированным из seed профиля** (закрывает наш остаток §4).
5. **Leak-тест матрица** — CreepJS/BrowserLeaks/BrowserScan + их debug-flowchart как
   основа авто-снимков E2E-стенда (`vento-test-env`), с усиленным критерием
   «идентичность между двумя разными машинами».
6. **Juggler-изоляция автоматизации** — положить в бэклог на случай авто-сценариев
   Vento; сейчас не приоритет.

**НЕ заимствовать:** их per-session рандомизацию canvas/metrics (обратна нашей
цели) и целиком их `MaskConfig`-инфраструктуру вместо RFP (увеличит расхождение с
upstream — мы сознательно строим на RFP-таргетах ради лёгких мерджей Firefox).

## 6. Вывод

Camoufox — **сильное подтверждение нашей архитектурной ставки** (движковый перехват
вместо JS-инъекции, консистентность профиля, база Firefox, WebRTC/IP на уровне
протокола) и одновременно **другой продукт**: он максимизирует правдоподобную
уникальность одноразовых личностей для автоматизации, тогда как Vento
максимизирует **детерминированную воспроизводимость одной личности между машинами**
для людей/команд.

Практическая ценность разбора — не «скопировать антидетект», а **забрать три вещи,
которых нам не хватает**: (1) источник правдоподобных согласованных значений
(BrowserForge + `webgl_data.db`), (2) готовую схему свойств профиля
(`properties.json`), (3) матрицу leak-тестов. При этом наши два дифференциатора —
**детерминированная межмашинная идентичность** и **проработанный сетевой отпечаток
§9** — у Camoufox отсутствуют, что и есть наше конкурентное преимущество.

Следующий шаг по задаче фингерпринтинга остаётся прежним (см. §«Первоочередные
шаги» FINGERPRINTING_RESEARCH), но п.1 (структура профиля + источник значений)
теперь можно ускорить, опираясь на `properties.json` и BrowserForge/`webgl_data.db`
из Camoufox.
